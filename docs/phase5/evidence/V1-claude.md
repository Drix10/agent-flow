# V1 Claude Code hook semantics (v2.1.287, Windows, haiku, -p). 13 live calls (2 wasted on my own test-harness bugs).
Docs: https://code.claude.com/docs/en/hooks , https://code.claude.com/docs/en/settings . NOTE: WebFetch summaries were LLM-paraphrased and in several places WRONG vs live (bypass+ask, trust, --bare); live results win.
Harness: hv-claude/ (project .claude/settings.json + hooks/stub.js + hook.log + run*.prompt/out).

Q1 exit codes. DOC: "Blocking error: your hook exits 2 ... Non-blocking error: any other code, or fails in some other way, such as not starting or printing invalid JSON. The action goes ahead". LIVE (-p, runA): exit0 ran; exit1 ran; exit2 BLOCKED (stderr shown to model: "PreToolUse:Bash hook error: [node hooks/stub.js pre]: stub exit2 BLOCKED-BY-STUB"); uncaught exception (node exit 1) ran; missing script path (`node hooks/does-not-exist.js`) + command-not-found (`nonexistentcmd_xyz`) alongside an exit0 hook -> command ran. => agent-flow assumption CONFIRMED. Doc: v2.1.295+ adds hook field `onFailure:"block"` (fail-closed for can't-start/exit!=0,2/timeout/bad JSON). LIVE on 2.1.287: Glob with a missing-script hook + onFailure:block was NOT blocked (field ignored on this version; needs >=2.1.295).
Q2 JSON. LIVE: exit0 + hookSpecificOutput.permissionDecision "deny" BLOCKS (reason reaches model, JSON-DENY-REASON). Legacy {decision:"block",reason} BLOCKS (reason delivered). "allow" lets through a command default perms would deny in -p (runC2, with user settings excluded). "ask" in -p: tool call DENIED (reason shown; no user to ask) both with --allowedTools Bash and default mode. Under --dangerously-skip-permissions (permission_mode=bypassPermissions in stdin): hooks STILL FIRE; "ask" -> denied, "deny" -> denied, exit2 -> blocked, plain -> ran. So hooks are NOT skipped by bypass and can tighten it. DOC: "Hooks can tighten but not loosen permissions"; exit 2 beats any JSON incl. allow. Interactive "ask" prompting not tested (needs TTY); doc says escalates to user.
Q3 timeout. DOC: default 600 s for command hooks (30 s for UserPromptSubmit), `timeout` seconds, "a timed-out PreToolUse hook doesn't block the tool call" (except onFailure:block). LIVE: timeout:2 + hook sleeping 6 s -> command RAN (fail-open).
Q4 coverage. LIVE with matcher "": hook fired for Write, Read, Edit, Glob, Agent (the subagent tool name is "Agent"), Bash. Regex matcher "Wri.*" matched Write. Hooks fire INSIDE subagents: stdin has agent_id + agent_type ("general-purpose"). DOC: matcher ""/"*"/omitted=all; letters/digits/_/,/| = exact list; any other char = unanchored JS regex; MCP `mcp__server__tool`, needs `mcp__memory__.*` (bare `mcp__memory` matches nothing); fires for all tools except EndConversation. MultiEdit/NotebookEdit/WebFetch/MCP: DOC only, not tested live.
Q5 UserPromptSubmit. LIVE (-p): FIRES in -p; stdin has `prompt` (full text), session_id, transcript_path, cwd, prompt_id, permission_mode, hook_event_name. JSON {systemMessage, hookSpecificOutput:{hookEventName:"UserPromptSubmit",additionalContext}} -> additionalContext reached model (it repeated the secret word), systemMessage emitted as a stream-json system/informational message (user-visible warning), prompt NOT blocked. exit 2 -> prompt blocked, model never called (num_turns 0, cost 0), result text = "UserPromptSubmit operation blocked by hook:\n[cmd]: <stderr>\n\nOriginal prompt: <full prompt echoed>"; `claude -p` process exit code was 0 and is_error false. DOC: also decision:"block", plain stdout (exit 0) added as context, 30 s default timeout; blocked prompt is erased from the transcript. Warn-without-block = exit 0 + systemMessage (+ additionalContext). Pasted secrets are only seen, not redactable (no updatedPrompt in docs).
Q6 precedence/tamper. DOC: managed > --settings > .claude/settings.local.json > .claude/settings.json > ~/.claude/settings.json; arrays merge (hooks from all scopes run); env block is an ordinary key so local overrides project (LIVE: hook env PROJ_ENV_TEST=from-local-settings with project=from-project-settings). `--settings '{"disableAllHooks":true}'` LIVE: exit2 hook bypassed (command ran). Managed hooks cannot be disabled by user/project/local disableAllHooks; `allowManagedHooksOnly` (managed) blocks user/project/local/plugin hooks. `--setting-sources project,local` LIVE: user settings (incl. user's allow:["Bash"] and user hooks) not loaded, project hooks still ran. `--bare`: CLI help says "skip hooks (those defined in settings and by installed plugins)"; not live-testable (needs ANTHROPIC_API_KEY, not set). Agent self-edit: LIVE non-bypass: Bash `echo '{}' > .claude/settings.json` hit the built-in permission gate ("Claude requested permissions to write to ...\.claude\settings.json, but you haven't granted it yet") even with --allowedTools Bash -> denied in -p. LIVE under --dangerously-skip-permissions: the redirect succeeded and the NEXT command in the SAME session ran un-hooked => settings edits take effect MID-SESSION (file watcher; doc: "edits to permissions, hooks ... without a restart"). Trust: LIVE project hooks RAN in -p in a brand-new directory with no trust entry in ~/.claude.json (hasTrustDialogAccepted absent) -> -p does not gate project hooks on trust (docs only mention trust gating for subagent/skill frontmatter hooks and permission allow rules).
Q7 inline env. LIVE: `FOO=1 echo ran > m_ok.txt` -> hook process FOO=null. CONFIRMED no. (Hook env does contain settings.json `env` block values and CLAUDE_PROJECT_DIR.)
Q8 stdin. LIVE PreToolUse keys (main): session_id, transcript_path, cwd, prompt_id, permission_mode, hook_event_name, tool_name, tool_input, tool_use_id; subagent adds agent_id, agent_type. No model field and no scratchpad_dir on 2.1.287. DOC: `model` only on SessionStart; also from_model/to_model on switch events; no $CLAUDE_MODEL. Audit id = session_id + prompt_id + tool_use_id + agent_id; model must come from transcript_path (jsonl) or SessionStart hook.
Q9 other weaknesses. Fail-open on missing script / crash / exit1 / timeout / bad JSON (until onFailure:block, >=2.1.295). Hook cmd relative path depends on cwd (use ${CLAUDE_PROJECT_DIR}). Agent in bypass mode can delete/rewrite hooks mid-session (edit tool or Bash). Anything that runs outside tool calls is not hooked: user `!` shell (doc), other processes the agent spawns (a script written then run is one hook event showing only the launch command), commands built dynamically. Hooks can't see inside `node x.js`. async:true hooks can't block. EndConversation skips hooks. Project hooks apply in -p without trust. User-level global hooks also run alongside (merge). Windows: user-level `allow: ["Bash"]` makes all Bash auto-allowed, so hook is the only gate.
Not verified: interactive TUI behaviour of ask/trust dialog; MultiEdit/NotebookEdit/WebFetch/MCP live; --bare live; background (run_in_background) Bash live; managed settings; whether user-level Bash allow lets agent write .claude/settings.json without prompt.
